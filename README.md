# ICOTAS

[**Intelligent Class Observation and Teaching Analytics System**](https://icotas.kesug.com)
ACLC College Tacloban City

ICOTAS is a native PHP 8 academic evaluation and teaching-analytics platform. It combines anonymous QR-based student evaluations, instructor-private analytics, rule-based sentiment and theme analysis, transparent trend indicators, class observations, ISO/IEC 25010 user acceptance testing (UAT), institutional reports, and a Dean/Academic Head administration console.

> **Implementation status.** The application is complete and has been validated locally against an isolated test database. It has **not** been deployed to or tested on InfinityFree. Compatibility with that host is a deployment target, not a verified claim. See `documentation/testing.md` for exact evidence.

## Stack

| Layer | Choice |
|---|---|
| Language | PHP 8.0+ (target PHP 8.4; verified on PHP 8.0.30) |
| Database | MySQL 5.7+ / MariaDB 10.3+ via PDO, `utf8mb4` |
| Web server | Apache with `mod_rewrite` (InfinityFree or XAMPP) |
| UI | Bootstrap 5.3.3, Bootstrap Icons 1.11.3, custom CSS |
| Theme | Blue primary (`#144a9c`), red accent (`#c62828`), white surfaces; semantic success/warning colors retained |
| Charts | Chart.js 4.4.4 (institutional and instructor dashboards) |
| QR | qrcodejs 1.0.0 for display, jsQR 1.4.0 for camera scanning |
| PDF | FPDF 1.9 with bundled JSON font metrics |
| Dependencies | None installed at runtime; all assets are vendored |

No Node, Python, PostgreSQL, Redis, WebSockets, cron, or external AI service is required. Reports are CSV or PDF. There is no email delivery; UAT invitations are copyable links.

## Fresh installation

### Browser installer (recommended)

1. Create an empty MySQL database and database user in the hosting control panel.
2. Upload the application so that `index.php` is directly inside the web root (`htdocs`).
3. Open `https://your-site/install.php`.
4. Enter the database credentials, site URL, and first Dean account.
5. The installer imports `database/schema.sql`, creates the Dean, seeds the standard survey templates and ISO/IEC 25010 UAT form, writes `config/local.php`, generates the private developer key, and creates `storage/installed.lock`.
6. Copy the private developer URL shown once on the success screen. It is used to issue Dean invitation codes and is never linked in the interface.
7. Delete `install.php` after success. The lock prevents reruns.
8. Sign in at `/login`.

The installer auto-creates a missing database only for `localhost`, `127.0.0.1`, and `::1`. On shared hosting, create the database first.

### Manual fallback

If the browser installer is blocked, follow `documentation/deployment-infinityfree.md#manual-installation-fallback`. In outline: create the database, import `database/schema.sql` through phpMyAdmin, copy `config/local.sample.php` to `config/local.php` with real credentials and a 64-character application key, insert a Dean whose password hash was generated by PHP `password_hash()`, then create the standard definitions in the interface (or run `php tools/seed_defaults.php` where shell access exists).

## Student account creation

Students can create their own account from the sign-in page at `/signup`. The public form is limited to the **student** role; instructor, academic-head, and Dean accounts are still issued by the academic office.

- Self-registration is unavailable while demo mode is active, so synthetic demo data cannot acquire live accounts.
- The Dean can close registration at any time under **Settings → Evaluation access → Allow students to create their own accounts** (`allow_student_signup`).
- A new account is active and marked `is_demo = 0`, but it is **not enrolled** in any class and receives no evaluation eligibility. Access to an evaluation still requires the instructor's roster and an active QR session.
- Controls: CSRF, hidden honeypot field, 8 attempts/hour per network, unique username/email/student number, and an 8+ character password containing a letter and a number. Each registration is recorded as `user.signup` in the audit log.

## Dean registration, invitation codes, and instructor accounts

Dean self-registration is **invitation-only**. It is not open public registration, because a Dean account has college-wide administrative access.

There are now **two supported ways** to add a Dean (or Academic Head) account:

1. **In the application, by a Dean** — open **Users → Administrators** (`/dean/administrators`). A Dean can:
   - create a Dean or Academic Head account directly, with a generated temporary password shown once (change required at first sign-in) or a password the Dean sets; and
   - issue or revoke **Dean invitation codes** so the recipient registers themselves at `/dean-signup` and chooses their own password.
2. **From the developer console** — the unlinked page whose URL is generated by the installer and stored as `developer_key` in `config/local.php`. It has no navigation entry; a wrong or missing key returns HTTP 404. Treat the URL like a password and rotate the key if it is exposed.

The administrator module is Dean-only. An Academic Head cannot open it, cannot be offered or forged into the Dean role, and cannot edit, deactivate, or reset the password of a Dean or another administrator. Every administrator creation, invitation, and revocation is written to the audit log, and creating accounts is rate-limited.

- **Invitation codes** created from either path are shown once and stored only as SHA-256 hashes.
- Codes are shown once at creation and stored only as SHA-256 hashes. They default to one use and seven days, can be limited to more uses or revoked, and are consumed inside the same database transaction that creates the account.
- **Dean sign-up** is available at `/dean-signup` only while demo mode is off and `allow_dean_signup` is enabled under **Settings → Evaluation access**. Deans choose their own password; no temporary password is issued.
- **Instructor accounts** are still created by the Dean under **User management**. The server generates a high-entropy temporary password and displays it once after creation. The account is flagged `must_change_password = 1` and is redirected to `/account/password` after sign-in; no other page opens until the password is replaced.
- Manual password resets by an administrator also sign the account out and force a new password at the next sign-in. Voluntary password changes are available from the account menu for every role.
- Existing installations must run `database/migrations/2026_11_10_dean_invites_and_forced_password.sql` before deploying the matching files. Fresh installs already include the changes in `database/schema.sql`.

## Research and AI labeling rules

- The sentiment and theme component is labeled **“Rule-Based AI-Assisted Sentiment and Theme Analysis”** (`rule-v1.1`). It is deterministic keyword/rule matching, not a trained language model.
- Prediction output is **rule-based trend estimation** using a weighted moving average and least-squares slope. It is **not** a validated machine-learning model, and no accuracy percentage is claimed.
- Mixed sentiment is reported as `mixed`; positive and negative signals are not averaged into a falsely neutral result.
- Existing reported research values, new implementation results, synthetic demo data, unvalidated predictions, and future work are kept distinct in `documentation/research-alignment.md`.
- The original research manuscript was not available in the repository when this documentation was written. Research-value comparisons are therefore limited to the requirements captured in the project brief and must be reconciled with the manuscript before publication.
