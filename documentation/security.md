# Security

## 1. Scope and honesty

This document describes controls implemented in the codebase and verified locally. It is not a penetration-test report or a certification. No third-party security audit has been performed. InfinityFree-specific behavior (WAF, `.htaccess` handling, PHP configuration) is untested.

## 2. Authentication

- Passwords are hashed with PHP `password_hash()` (bcrypt/Argon2 depending on runtime defaults) and verified with `password_verify()`.
- Rehash on successful login when `password_needs_rehash()` reports an outdated algorithm.
- Inactive accounts are rejected at login.
- Per-account/IP lockout: 5 failed attempts in 15 minutes (`login_attempts`).
- Per-IP ceiling: 100 login POSTs in 15 minutes (`rate_limits`), intentionally high for shared campus NAT.
- Session ID regenerated on login; CSRF token rotated.
- Login/audit IP addresses stored as HMAC-SHA-256 using the application key, not plaintext.
- Failed attempts are recorded even when the lockout is already active, which extends the lockout window under sustained attack.

## 3. Session protections

`Session::start()` sets:

- `session.use_only_cookies = 1`
- `session.use_strict_mode = 1`
- `cookie_httponly = 1`
- `cookie_samesite = Lax`
- `cookie_secure` when HTTPS is detected (directly or via `X-Forwarded-Proto`)
- 2-hour idle timeout
- Session ID regeneration on privilege transition

`user_sessions` records a SHA-256 hash of the session ID, user, hashed IP, user agent, and last activity. The table supports revocation/audit; current UI does not expose remote session management.

## 4. CSRF

Every state-changing request (POST/PUT/PATCH/DELETE) is validated by `Csrf` **before** the route runs. Tokens are per-session, rotated on login, and checked with `hash_equals()`. There is no per-form exemption. JSON clients can send `X-CSRF-Token`.

A missing or stale token returns HTTP 419 with a friendly page or JSON error.

## 5. Output and input safety

- All HTML output is escaped through `e()` (or view-specific formatting helpers).
- PDO native prepared statements are used for values. Dynamic identifiers are allowlisted (for example report type, academic entity, sort column).
- Free text is cleaned of control characters and length-limited.
- CSV import validates extension, size, required headers, e-mail format, role allowlist, and duplicate codes; it is parsed server-side and never executed.
- CSV exports quote fields via `fputcsv`; PDF output is generated by FPDF from escaped/plain data.
- CSP restricts scripts/styles/images to self (inline is allowed because the server-rendered Chart.js configuration and CSRF meta tag require it). `frame-ancestors 'none'`, `X-Frame-Options: DENY`.
- `X-Content-Type-Options: nosniff`, strict referrer policy, and a restrictive permissions policy are set.

## 6. Cryptography

| Purpose | Primitive |
|---|---|
| QR / UAT token generation | `random_bytes(32)` / `random_bytes(24)` |
| Token lookup | SHA-256 |
| Token re-display | AES-256-GCM (`v1:` format: IV + tag + ciphertext) |
| IP pseudonymization | HMAC-SHA-256 with application key |
| Passwords | PHP `password_hash()` |
| CSRF token | `random_bytes(32)` |

The application key in `config/local.php` must be a random 64-character hex string. It is not a password and must not be reused across installations. Rotating it invalidates encrypted token re-display and changes IP hashes; it does not delete data.

## 7. Authorization

See `rbac.md`. Route middleware and controller-level object checks are both required. UI hiding is not a control. Instructor queries are scoped to the authenticated instructor; student access requires eligibility and a pending participation row.

## 8. Anonymity controls

See `anonymity.md`. Response tables contain no student key; submission is transactional; timestamps are hour-bucketed. Comments are suppressed below the privacy threshold. Residual risks (small cohorts, distinctive text, DB access, timing correlation) are documented rather than denied.

## 9. File and directory protection

Root `.htaccess`:

- Disables directory indexes.
- Denies `app/`, `config/`, `database/`, `documentation/`, `storage/`, `tests/`, `tools/`.
- Routes non-file/non-directory requests to `index.php`.
- Denies hidden files, `local.php`, SQL/log/lock/MD/INI/env/backup files.

`assets/.htaccess` denies PHP/CGI execution. `config/`, `database/`, `storage/`, `documentation/`, `tests/`, and `tools/` each have their own deny file.

**This protection is Apache-specific.** On Nginx or a server that ignores `.htaccess`, the web root must be configured to deny those directories and to route requests to `index.php`. Do not deploy on such a server without equivalent configuration.

## 10. Installer security

- Requires a CSRF token and a valid database connection.
- Refuses to run when `storage/installed.lock` exists.
- Validates database name, port, URL, and a strong Dean password (12+ characters, 3 character classes).
- Writes `config/local.php` via a temporary file + rename, then `chmod 0640`.
- Writes `storage/installed.lock` with installation metadata.
- Auto-creates a database only on localhost/loopback; shared hosting must create it first.
- **After installation, delete `install.php`.** The lock is a safety net, not a reason to leave the installer online.
- If `config/local.php` and the lock must be removed for a deliberate reinstall, back up first and restrict access during the operation.

## 11. Error handling and logging

- Production (`debug=false`) hides exception details and logs them to `storage/logs/php-error.log`.
- HTTP errors render a consistent page or JSON.
- Audit records are best-effort: a logging failure does not break the business action, but it is written to the PHP error log.
- Do not enable `debug` on a public host; it reveals file paths and messages.

## 12. Known limitations and residual risks

| Risk | Note |
|---|---|
| No MFA | Dean accounts are high-value; add MFA if the host supports it. |
| No password-reset flow | `password_reset_tokens` is reserved; administrators reset passwords manually. |
| No security headers at the host edge | Application headers are set, but the hosting provider may add/override. Verify. |
| `.htaccess` dependence | Non-Apache hosts need equivalent deny rules. |
| Shared hosting | Provider staff and other tenants are outside the application trust boundary. |
| No WAF guarantee | InfinityFree may have its own filtering; behavior is untested. |
| No per-token brute-force counter | Manual code space is large; login is throttled. Add a counter if threat modeling requires it. |
| CSV formula injection | Exported CSV may be opened in a spreadsheet; values beginning with `=`, `+`, `-`, `@` are not neutralized. Treat exports as data, or add neutralization if required. |
| Audit timing | Exact audit/participation timestamps can aid inference in very small cohorts. See `anonymity.md`. |
| No formal pen test | Hire an independent tester before high-stakes production use. |

## 13. Hardening checklist

- [ ] HTTPS enabled and forced by the host.
- [ ] `config/local.php` not readable over HTTP.
- [ ] `install.php` deleted after installation.
- [ ] `storage/installed.lock` present and not web-readable.
- [ ] Application key unique and random.
- [ ] Database user limited to the application database (no `GRANT ALL` on `*.*`).
- [ ] Demo data off and removed before real use.
- [ ] Default/demo passwords changed or accounts deleted.
- [ ] Privacy threshold set to at least 3.
- [ ] Backups encrypted and access-controlled.
- [ ] PHP `display_errors=Off` in production.
- [ ] Error log not web-readable.
- [ ] Host PHP version checked against the target.
- [ ] UAT and evaluation notices reviewed by the institution's data-protection officer.
